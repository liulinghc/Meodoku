## 0. 设计原则（先立规矩，后谈功能）

| # | 原则 | 落地含义 |
|---|---|---|
| 1 | **离线可完整运行** | 除激励视频外，任何功能不依赖网络。广告拉不到 = 入口隐藏，绝不阻塞 |
| 2 | **零后端** | 不注册、不登录、不上传任何用户数据。所有状态在本地 Storage |
| 3 | **算法产内容** | 关卡由生成器批量生产，人工只做抽检与参数调优，绝不手搓关卡 |
| 4 | **唯一解是硬约束** | 无法通过对局验证唯一解的关卡一律不进包；生成失败的候选直接丢弃 |
| 5 | **玩家永不遇到死局** | 生成从"合法解"出发 → 区域划分 → 求解器验证唯一性，三重保障 |
| 6 | **性能预算前置** | 低端机预算写在架构里（见 I.10），不是上线前再优化 |
| 7 | **分层硬边界** | `domain/` 是纯函数层，可在 Node 里跑测试和生成；`platform/` 是唯一碰 `wx.*` 的地方 |
| 8 | **允许玩家犯错，不允许玩家困惑** | 不拦截错误操作，但给出即时、克制的冲突反馈 |

## A. 产品方案

### A.1 一句话定位

> 每天三分钟，解开一盘猫咪方阵——规则十秒学会，关卡无限生成，不用联网。

- **品类**：逻辑解谜 / 变格数独（Queens / Star Battle 单星变体）
- **平台**：微信小游戏（纯原生 JS + Canvas 2D）
- **目标人群**：25–45 岁为主的轻度解谜用户（女性占比可预期偏高）、通勤与睡前碎片时间
- **核心体验关键词**：治愈、确定感、掌控感、收集欲
- **商业模型**：IAA（激励视频）为主，无内购、无强制广告

### A.2 与参考产品的差异化（合规且不抄袭）

玩法内核属于**公开的数学谜题类型**（每行每列每区各一、互不八邻接），类型本身不受保护；受保护的是**名称、美术、UI 版式、具体关卡数据**。因此：

- ❌ 不使用近似名称（`Meowdoku`、`Meowdoku: Brain Puzzle Games` 及其变体）
- ❌ 不复制其图标、猫咪素材、配色方案、界面布局、关卡画布
- ✅ 原创视觉语言：手绘暖色系、纸张质感、圆润几何、猫爪符号系统
- ⚠️ "美术方向一致"指**风格调性对齐**（治愈、柔和、糖果色、圆角），**不包括**复用其素材文件、图标、插画构图与 UI 版式；所有资产重新绘制（详见 C.8）
- ✅ 原创交互层：三态循环点击、自动排除、思路提示、章节地图、收集图鉴
- ✅ 原创内容层：区域配色算法、难度评分体系、章节主题

### A.3 名称（已确认：《喵喵迷阵》）

> 提交前仍须完成：① 中国商标网近似检索（第 9/41 类）② 微信小游戏名称查重 ③ 拼音/英文名检索（分享文案会用到）。名称确认不等于商标无冲突，检索成本很低，别省。

### A.4 内容规模（首发）

| 内容 | 数量 | 来源 |
|---|---|---|
| 主线关卡 | **300 关（15 章 × 20 关）** | 生成器批量产出 + 自动筛选 |
| 每日挑战 | 365 天预置 | 生成器预计算日历 |
| 猫咪图鉴 | **16 只**（数据结构预留 24+） | 数据表配置 |
| 章节主题 | 6 套配色 + 装饰（15 章复用） | 原创设计 |
| 无尽模式 | v2，不首发 | 运行时按种子生成（复用同一生成器） |

> 300 关是**验证规模**，不是终局规模。生成管线建好后，扩到 600 关只是重跑批处理，
> 产物会重新全局排序，旧关卡按稳定 ID 保留；这是"算法产内容"的直接收益。

### A.5 商业与合规

- 收入 = 激励视频（主要）+ 插屏（克制、低占比）
- 不做内购 → 免去支付资质与未成年退款风险
- 上线前核对清单：类目资质（休闲游戏类）、软著、流量主开通条件、隐私保护指引、广告合规（可关闭、不诱导、奖励透明）、适龄提示
- **注意**：微信平台规则变动频繁，以上仅为设计约束项，具体资质以最新官方文档为准

## B. 核心循环

### B.1 四层循环

```
┌─ 秒级：认知循环 ─────────────────────────────────┐
│ 点格子 → 看见排除联动 → 发现唯一候选 → 放猫      │
│ 目标：每 5~15 秒一次"啊哈"                        │
└──────────────────────────────────────────────────┘
          ↓
┌─ 关卡级：3 分钟循环 ─────────────────────────────┐
│ 进入关卡 → 推理/标记 → 完成 → 结算 → 金币/猫爪     │
│ 目标：一关 30 秒~5 分钟，可随时中断续玩            │
└──────────────────────────────────────────────────┘
          ↓
┌─ 会话级：5~15 分钟 ──────────────────────────────┐
│ 每日签到 → 每日挑战 → 主线 2~4 关 → 图鉴/商店      │
│ 目标：一次会话完成 1 个"有进展"的目标              │
└──────────────────────────────────────────────────┘
          ↓
┌─ 长线：天/周 ────────────────────────────────────┐
│ 章节推进 → 猫咪收集 → 连胜签到 → 成就              │
│ 目标：明天再来的三个理由                          │
└──────────────────────────────────────────────────┘
```

### B.2 会话目标（每个会话给玩家一个"必须完成"的事）

- 打开即见：今日挑战倒计时 + 签到小红点 + 当前关卡"还差 3 关解锁新猫"
- 首次会话：启动先弹 3 页玩法说明（目标 → 单击打叉 / 再点放猫 / 再点清空 →
  工具与新手保护）→ 约 3 分钟教学段（前 10 关 4×4，第 1–3 关预放 3/2/1 只猫，
  第 4 关高亮突破口，无广告）→ 首通第 1 关立即解锁第 1 只猫
- 新规则分步出现：预放猫、行列、区域、高亮、免费提示、打叉、大棋盘首次出现时
  各弹一次规则卡；规则卡显示期间暂停计时，不一次性铺满所有规则
- 流失防线：引导关（前 10 关）连续 3–10 秒无操作（第 1 关 3 秒，逐关放宽，
  第 10 关 10 秒）→ 在下一处正确落子格显示“点两下”脉冲引导
  （该格已打叉则显示“点一下”）；连续 20 秒无操作 →
  温和提示并点亮提示按钮；前 10 关提示免费；
  前 5 关首次违规只提示、不施压；所有失误可撤销

### B.3 留存钩子设计

| 时间点 | 钩子 | 机制 |
|---|---|---|
| 当日 | 每日挑战 | 每天 1 局，同样种子，连胜奖励递增 |
| 次日 | 签到 | 7 日循环 + 累计里程碑 |
| 3 日 | 主题解锁 | 通关第 2 章解锁 1 套棋盘主题 |
| 7 日 | 稀有猫 | 第 1 只稀有猫在 7 天签到完成时解锁 |
| 长期 | 图鉴完成度 | 16 只猫 + 6 套主题 |

### B.4 节奏与疲劳控制

- 档位按章节成段推进，同档内尺寸与难度分递增；第 14–15 章共 30 关为 T5 收官段（见 D.3）
- 单局连续失败 3 次：自动提示"要不要换一关？"（不强制）
- 单日主线推进超过 10 关：结算页弱化"继续"按钮，展示图鉴引导休息

## C. 界面设计

### C.1 信息架构

```
启动/加载
 └─ 主界面 (Home)
     ├─ 主线 → 关卡地图 (Level Map) → 游戏 (Game) → 结算 (Result) → 下一关/返回
     ├─ 每日 → 每日挑战 (Daily) → 游戏 → 每日结算
     ├─ 签到 (Sign-in，弹层)
     ├─ 图鉴 (Collection) → 猫咪详情
     ├─ 商店/兑换 (Shop)
     └─ 设置 (Settings)
```

### C.2 主界面

```
┌──────────────────────────────────────┐
│ [头像=当前装备猫]  Lv.12    🪙 380  🎫 3 │  ← 顶部资源条（安全区内）
│                                      │
│             喵 谜 格                  │
│          猫 咪 逻 辑 方 阵            │
│                                      │
│        ┌──────────────────┐          │
│        │  今天的猫（3D/2D  │          │  ← 主视觉：当前猫咪大图
│        │  呼吸动画）       │          │
│        └──────────────────┘          │
│                                      │
│         [  继 续 第 12 章  ]          │  ← 主 CTA，唯一高亮
│                                      │
│   ┌────────┐  ┌────────┐  ┌────────┐ │
│   │ 每日挑战│  │  图 鉴 │  │  商 店 │ │  ← 次级入口，三宫格
│   │ 2:34:10│  │ 8/24   │  │ 🎫 3   │ │
│   └────────┘  └────────┘  └────────┘ │
│                                      │
│           [签到  ●]      [⚙ 设置]     │
└──────────────────────────────────────┘
```

设计要点：

- **单一主 CTA**：只有一个高亮按钮，其余入口做视觉降权
- 主视觉猫咪承担"情绪锚点"，每次打开首页变化（今日推荐猫）
- 资源条常驻但不可点击（点击进商店/图鉴），避免误触
- 首次进入 ≤ 2 秒出现可交互元素；加载期间用骨架屏 + 猫爪进度

### C.3 关卡地图

- **形式**：竖向路径（自上而下或自下而上推进），章节横向切换（左右箭头）
- **节点状态**：已完成（实心 + 猫爪评分）/ 当前（脉冲高亮）/ 未解锁（灰化 + 锁）
- **章节卡片**：章节名、进度条（12/20）、代表色、封面装饰
- **顶部**：章节选择条 + 总进度
- **交互**：点节点进关；长按预览关卡信息（尺寸、难度、最佳记录）；左右箭头切章节
- **锁关**：只能进入 `unlocked` 前沿内的关卡；章节起点未解锁时，向前切章被拦截并提示。
  地图以外的入口（对局场景、结算“下一关”）同样校验，不能靠跳转越过解锁链
- **性能**：只渲染视口内 ±1 屏节点，其余不绘制（虚拟列表）

### C.4 游戏界面

```
┌──────────────────────────────────────┐
│ (←)      Level 3 · 第 12 关     (⚙)   │  ← 顶部栏：圆形按钮 + 居中两行
│                                      │
│   🐱 🐱 🐱 🐱 🐱                      │  ← 区域图例条：N 个色块猫头
│  ┌────┐ ┌────┐ ┌────┐                │
│  │每区一猫│ │行列各一│ │猫不相邻│      │  ← 规则卡（N≥8 可折叠）
│  └────┘ └────┘ └────┘                │
│         [ 区域色块棋盘 N×N ]           │
│         猫 / X / 空 三态               │
│                                      │
│  ～～～  (↩)   (🗑)   (💡)  ～～～     │  ← 三个圆钮坐在底部色带上
│          今日目标提示                  │
└──────────────────────────────────────┘
```

- **棋盘占屏宽 86%~92%**，保持正方形，居中；上下留 HUD/工具栏呼吸位
- **区域着色**：12 色候选按该关区域相邻图分配，相邻区优先取 CIELAB 色差最大的颜色
  （ΔE ≥ 30），全盘惩罚近色；不叠加纹理，结果确定且每关不同
- **三态点击**：空 → 猫 → X → 空（默认）；设置里可改为"长按直接标 X"/"两态模式"
- **自动排除**（默认开）：放猫后自动把同行、同列、同区、八邻域标 X，可撤销整体回退
- **冲突反馈**：违反规则时当场标红抖动，但**不阻止**放置
- **完成判定**：N 只猫、每行/列/区恰好 1 只、无八邻接 → 剩余空格自动补 X → 0.3 秒判定动画 → 猫群庆祝
- **中断续玩**：切后台/退出自动存档当前盘面（含 X 标记与撤销栈不保存，只保存盘面）

### C.5 结算界面

- 布局：奖牌/猫爪评分 → 用时/步数 → 奖励清单（金币、碎片）→ "看视频 ×2" → [下一关] / [返回地图]
- **分阶段入场**：猫 → 标题 → 猫爪 → 数据 → 奖励 → 按钮，每段 90–120ms；
  猫爪逐枚盖章，用时/步数从 0 滚动，新纪录在信息卡右上角盖缎带角标；
  彩纸分远近两层（合计 24 片），金币奖励向外放射一次。
  动效只影响绘制、不锁输入，跳过动画时按钮仍可点击。
- **猫爪评分**（非星级，避免"时间压力"背离解谜气质）：

| 评分 | 条件 |
|---|---|
| 1 🐾 | 通关 |
| 2 🐾🐾 | 全程未使用提示 |
| 3 🐾🐾🐾 | 未使用提示 + 未出现错格 |

- 撒花、猫爪落下的粒子效果克制、时长 ≤ 1.2 秒（低端机可关）

## D. 关卡难度递增机制

### D.1 难度由哪些参数决定

| 参数 | 影响 | 权重 |
|---|---|---|
| 棋盘尺寸 N | 基础复杂度 | 18% |
| 假设次数 `branchCount` / 失败分支 `failedBranches` | 是否需要猜、猜错几次 | 30% |
| 推理工作量 `placements + lockSteps` | 玩家要放多少猫、做多少次锁定 | 18% |
| 打叉负担 `marks` | 玩家要点多少次 X | 14% |
| 锁定候选 `lockSteps` | 是否需要组合行列/区信息 | 10% |
| 开局开放度 `avgCellOptions` | 开局是否"有抓手" | 5% |
| 预放猫 `givenCount` | 开局已给出多少只 | 减 8% |

> 区域形状、尺寸方差、对称性只作结构过滤与视觉多样性，不直接计入难度分。
> 预放猫在开局先落子，因此会真实降低候选数、提供突破口，并按比例减分。

### D.4 难度评分是"算出来的"，不是"感觉出来的"

每个候选关卡跑一遍**人类技巧求解器**（`js/domain/human.js` + `difficulty.js`，
见 I.6.4），规则集 P1–P4：放置排除 → 唯一候选 → 锁定候选 → MRV 假设验证
（节点上限 40000）。输出 `givenCount`、`placements`、`marks`、`lockSteps`、
`branchCount`、`failedBranches`、`initial` 等指标，并按下列公式取整（0–100）：

```
sizeF   = (N - 4) / 5
guessF  = min((branchCount + 0.5×failedBranches) / 3, 1)
workF   = min((placements + lockSteps) / (playable × 2), 1)
markF   = min(marks / N², 1)
lockF   = min(lockSteps / (playable × 1.5), 1)
openF   = min(avgCellOptions / N, 1)
givenF  = givenCount / N
raw     = 100 × (0.18×sizeF + 0.30×guessF + 0.18×workF
               + 0.14×markF + 0.10×lockF + 0.05×openF)
        - 100 × 0.08 × givenF
score   = clamp(round(raw), 0, 100)
```

按 `40 / 55 / 70 / 80` 切五档，再按尺寸上下限夹紧（见 D.2）；
`branchCount > 0` 时分数至少 40（不得评 T1）。求解器完全确定性，
同一盘面 + 同一组预放猫永远得到同一个分数；1000 关批量实测分数 32–93，平均 57.2。

### H.2 激励视频状态机

```
idle ──show()──> loading ──onLoad──> ready ──play──> playing
                                          │
                          onClose(isEnded) ──true──> grant() ──> idle
                                          └─false──> idle（不发奖，提示"完整观看才可领取"）
onError ──> retry(≤2, 指数退避) ──> unavailable ──> 隐藏入口
```

实现要点：

- **启动时创建一次** `wx.createRewardedVideoAd({adUnitId})` 单例，注册 `onLoad/onError/onClose` 一次，避免重复监听
- 必须在 `onLoad` 成功后才允许播放；未加载完点击 → 先 show 再等就绪或给 loading 态
- 奖励发放以 `onClose` 的 `res.isEnded` 为准
- 返回前台（`wx.onShow`）时尝试重新 load，修复"拉取失败后永久不可用"
- 所有广告位共用 1 个单例（微信同一 adUnit 复用），不同 adUnit 按需拆分

### H.3 体验红线

- 广告绝不打断解谜过程；不出现"关闭按钮隐藏 3 秒"
- 不给"广告专属关卡/道具"（不制造付费墙）
- 不诱导分享、不诱导关注
- 未成年人：无内购、无社交，适龄提示

### H.4 收益预期

IAA 收益 ≈ DAU × 人均观看次数 × 完播率 × eCPM / 1000。首版目标：人均 1.5–3 次/日，eCPM 区域差异极大，**不在架构层面做任何收益承诺**，只保证广告位可配置、可关闭、可灰度。

## I. 技术架构

### I.1 分层与依赖方向

```
        ui/ (screens, widgets, renderer)
                 │  只调用 ↓
        services/ (progress, economy, daily, ...)
           │            │
           ↓            ↓
      domain/       platform/   ← platform 是唯一 import wx.* 的层
    （纯逻辑，无平台依赖）
           ↑
        data/ (config, cats, level packs)
```

**硬规则**：

- `domain/` 不出现 `wx.`、不出现 `canvas`、不出现 `Date.now()`（时间从外部注入）
- `services/` 可以依赖 `domain` + `platform`，不可直接碰 Canvas
- `ui/` 只通过 `services` 拿数据，不直接读 Storage
- 所有模块使用 **CommonJS**（`require` / `module.exports`），不用打包器，`tools/` 里的 Node 脚本可以直接复用 `domain/`

### I.2 运行时

- 入口 `game.js` → `js/main.js`（引导）→ `App`（生命周期）→ `SceneManager`
- 主循环：`requestAnimationFrame`，**事件驱动 + 脏标记**；无动画时降为按需渲染
- 场景栈：`boot → home → levelmap → game → result`，支持弹层（签到、设置、详情）叠加
- 前后台：`wx.onHide` 立即落盘 + 暂停计时；`wx.onShow` 校准时间差（用于挂机计时）

### I.3 渲染方案（Canvas 2D，无引擎）

**屏幕只有一张主 Canvas**：

| 层 | 载体 | 重绘时机 |
|---|---|---|
| L0 棋盘静态层 | 离屏 Canvas（整块棋盘：背景、区域色块、网格线、装饰） | 换关/换主题/尺寸变化 |
| L1 棋子层 | 主 Canvas 直接绘制（猫、X、选中、冲突） | 每次操作 |
| L2 UI 层 | 主 Canvas（HUD、按钮），面板缓存到离屏 | 状态变化 |
| L3 特效层 | 主 Canvas（飘字、粒子、猫爪） | 动画期间 |

每帧顺序：`drawImage(L0)` → 绘制 L1 → 绘制 L2 → 绘制 L3。

性能要点：

- `devicePixelRatio` **上限 2** 并取整，避免 3x 屏超采样
- **禁止**每帧使用 `shadowBlur`、`createLinearGradient`、`filter`（低端机杀手）；阴影一律预渲染进图片
- 文字提前测量并缓存；静态文案预渲染到离屏
- 绘制调用目标 ≤ 60 次/帧；N≤10 时棋盘格子 ≤ 100，远低于阈值
- 粒子/飘字对象池化；热路径零闭包、零临时数组
- 切换场景时释放离屏 Canvas 与图片引用，防内存增长

### I.4 输入

- 统一在 `platform` 层注册 `wx.onTouchStart/Move/End/Cancel`，转成逻辑坐标（考虑 devicePixelRatio 与 safeArea）
- `InputManager` 输出语义事件：`tap / longPress / dragStart / drag / dragEnd`
- 判定：tap = 按下到抬起 < 250ms 且位移 < 12px；长按 = 400ms
- 命中测试用矩形/圆形区域数组，按 z 序倒序检测
- 左利手模式：镜像工具栏位置

### I.5 存档

| 项 | 设计 |

### I.6 关卡生成 / 答案验证 / 唯一解验证（核心）

#### I.6.1 规则形式化

N×N 棋盘，分为 N 个区域，放置 N 只猫，满足：

1. 每行恰好 1 只
2. 每列恰好 1 只
3. 每个区域恰好 1 只
4. 任意两只猫的切比雪夫距离 > 1（上下左右与斜对角相邻都不行）

#### I.6.2 生成管线（v1 全离线批处理；v2 复用于无尽模式）

```
[1] 选参数      N、目标档位、随机种子
        ↓
[2] 造答案      回溯随机生成满足 1/2/4 的列排列（8 邻接约束）
        ↓
[3] 划区域      以 N 个答案格为种子多源 BFS 生长，区域连通且各含 1 个答案格
        ↓
[4] 结构校验    连通/尺寸/长条/包围盒/周长/整行列等阈值过滤
        ↓
[5] 唯一性验证  求解器计数到 2 即停；0 解丢弃，≥2 解进入定向修补
        │        节点上限 200k，超限 → 丢弃（视为病态候选）
        ↓
[6] 定向修补    对双解候选重划区域边界，要求仍含原答案且解唯一
        ↓
[7] 难度评分    P1–P4 人类技巧求解器（含预放猫），输出打叉/锁定/假设/分数/档位
        ↓
[8] 分档筛选    档位不符 → 丢弃并换种子重试
        ↓
[9] 去重打包    规范化签名（区域重标号 + 8 种对称）去重，排序后写 JSON/JS
        ↓
[10] 复验       全量重解 + 配额/尺寸/档位/哈希校验 + 人工抽检 1%~5%
```

**关键设计**：生成永远从"一个真实存在的合法解"出发，因此**新关必然可解**；唯一性由求解器保证，因此**玩家不可能遇到多解**（多解在该玩法中会表现为"猜对却被判错"，是最伤体验的缺陷）。

#### I.6.3 求解器（唯一解验证）

- 逐行放置，状态用位掩码：已用列、已用区域、上一行猫的列号
- 候选列 = 未使用 ∧ 与上一行列距离 > 1 ∧ 所在区域未使用
- 剪枝：
  - 剩余行数 < 剩余未用区域数 → 剪
  - 某未用区域在剩余行中已无合法格 → 剪
  - 某未用区域只在某一行有合法格 → 该行强制绑定
- 计数到 2 立即返回；找到 1 解时同时输出答案
- 实测 N ≤ 9 单次计数通常在 5ms 内完成；v2 运行时生成（无尽模式）加 150ms 时间片上限，超时降级到预置池

#### I.6.4 人类技巧求解器（难度评分）

规则集（逐步应用，直到无法推进）：

| 编号 | 技巧 | 说明 |
|---|---|---|
| P1 | 放置排除 | 放猫后同行/同列/同区与 8 邻域全部打叉 |
| P2 | 唯一候选 | 某行/列/区只剩 1 个候选格 → 放猫 |
| P3 | 锁定候选 | 某区候选全在同一行/列（或行列候选全在同一区）→ 其余格排除 |
| P4 | 假设验证 | MRV 选格分支试放，矛盾则回退（计入 `branchCount` / `failedBranches`） |

开局先落预放猫，因此候选数、突破口与打叉负担都计入真实门槛。
分支搜索设节点上限 40000，超限的候选直接淘汰、不入池。
档位由尺寸、假设、推理工作量、打叉、锁定、开局开放度与预放猫加权算出（见 D.4）；
`branchCount > 0` 的题不得评 T1，教学/入门关因此全部零假设。

#### I.6.5 答案验证（对局内）

- **规则验证**（唯一正确路径）：每放一只猫，检查行/列/区/邻接四条规则，O(N)
- **不依赖答案数组**做胜负判定 → 即使关卡数据被篡改也不会出现"正确排列被判错"
- 提示功能才读取答案（`sol`），用于给出一只正确的猫
- 结算时二次校验（防止撤销/存档异常导致的脏状态）

#### I.6.6 关卡数据编码

每关紧凑编码，1 格 1 字符：

| 字段 | 说明 | 大小（N=9） |
|---|---|---|
| `id` | 稳定 ID（L001–L300；扩产时旧 ID 不变） | — |
| `n` | 尺寸（4–9） | — |
| `r` | 区域串，n² 个字符 `a–i` | 81 字符 |
| `s` | 答案串，每行猫的列号 `0–8` | 9 字符 |
| `t` | 难度档 1–5 | 1 字符 |
| `d` | 难度分 0–100 | 1–3 字符 |
| `b` | 分支数（评分过程产物） | 1 字符 |
| `seed` | 生成种子（复现用） | — |

包级字段：`schema`、`generator`（如 `md-levelgen/2`）、`total`、`names`、`hash`。
300 关紧凑数据 35KB（JS 包装 35KB），JSON 源 57KB（仅构建用，不打包）。
当前单包直接 `require`；进一步扩产时可拆包，`levels/index.js`
追加一行 require 即可，业务侧仍只认全局 1-based 序号。

#### I.6.7 每日挑战与运行时出题（v2）

- **主线（S4 已完成）**：300 关全部离线预生成，客户端零生成开销、零踩坑面
- **每日（S5 已完成）**：`levels/daily-365.js` 预置 365 道（312 工作日 + 53 周日），
  与主线布局签名去重、池内无重复；周日取周日池、其余取工作日池，按本地日期取池内序号，
  同一日期全设备同题，跨年循环复用，不受版本更新影响。S5.1 起题目内容不变，
  只按新人类求解器重评档位（当前实际档位 `{T2:105,T3:234,T4:26}`）
- **运行时生成器**：`js/domain/generate.js` 与离线工具共用同一管线，可本地动态出题；
  S3 已通过 1000 关批量验证，可作为未来无尽模式 / 兜底出题能力
- **v2 无尽模式**：种子 = `hash("endless:" + gameVersion + ":" + runIndex)`，运行时用同一生成器出题并立即自验，失败换种子（≤5 次），届时再评估性能与降级策略
- 生成器版本号写入关卡数据；算法升级时旧关卡不变（已硬化进包）

### I.7 提示系统

提示分三级，由浅到深（成本递增）：

| 级别 | 内容 | 成本 | 实现 |
|---|---|---|---|
| 思路 | 高亮一个"当前最少候选"的区域/行 | 免费（3 次/日） | 从当前盘面跑传播，找出候选数最少的单元 |
| 排除 | 标记一个确定为空格的 X | 15 金币 | 答案格取反，且该格当前为未知 |
| 放猫 | 放下一只正确的猫 | 1 提示券 | 基于"当前盘面可推理出"的答案格优先（而非随机），更像"老师带你走一步" |

**智能提示算法**：从当前盘面跑一次局部传播（R1–R3），若存在可推导结论，优先给出该结论；否则才直接取答案。避免"提示跳步"导致玩家失去理解。

## K. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 区域划分导致多解率高，生成效率低 | 内容产能不足 | 加大重试预算、放宽尺寸方差、先用 N=5–7 验证管线 |
| 唯一解求解在大 N 上抖动 | 生成卡顿 | 节点上限 + 超时丢弃 + 预生成入库 |
| 低端机 Canvas 掉帧 | 首秀差评 | 静态层预渲染、DPR 上限 2、禁用实时阴影/渐变、动画可关 |
| 广告填充率低 | 收益不达预期 | 所有入口可降级隐藏；核心玩法零广告依赖 |
| 名称/视觉近似侵权 | 下架风险 | 原创命名、原创素材、不做像素级复刻；上架前检索 |
| 平台类目/资质不符 | 审核被拒 | 提前确认类目、软著、流量主门槛 |
| 本地时间作弊 | 奖励通胀 | 止损式校验（见 G.3），不追求绝对防护 |
| 难度主观偏差 | 挫败/无聊 | 指标化难度 + 前 100 关真人测试校准 |

# 关卡生成与验证算法设计 v1.0

> S3 阶段施工图。实现时 `js/domain/` 与 `tools/` **复用同一份 CommonJS 模块**——生成器与运行时共用一套规则，避免"两套逻辑不一致"这类最难查的 bug。
> 本文只描述算法，不含代码。

---

## 0. 什么叫"这关是对的"

六条不变量，任何一条不满足 → 候选直接丢弃，不得进包。

| 编号 | 不变量 | 验证方式 | 违反后果 |
|---|---|---|---|
| INV-1 | **解唯一** | 求解器计数，收到 2 即停 | 提示可能给错、评分失真 |
| INV-2 | **解合法** | 规则校验（N 只猫、行列区各 1、无八邻接） | 关卡不可通关 |
| INV-3 | **区域连通** | 4 邻接 BFS 覆盖区域全集 | 视觉歧义、玩家看不懂 |
| INV-4 | **区域与解一一对应** | 每个区域恰好含 1 个解格 | 规则自相矛盾 |
| INV-5 | **可复现** | 同 version + 同 seed → 逐字节相同 | 无法定位坏关、无法回归 |
| INV-6 | **可读** | 区域尺寸/形状/配色在阈值内 | 体验崩坏（不是数学问题，但同样拒收） |

两点重要认识：

1. **唯一解不是为了"防止玩家作弊"**。胜负判定走规则校验（§9），不比对答案数组。即使某关意外多解，玩家用另一种摆法也能通关，不会被判错。唯一解真正保护的是**提示功能、难度评分、内容一致性**。
2. **可解性是结构性保证，不是概率保证**。因为生成从"一个真实解"出发（§3），"无解关卡"在流程上不可能出现——不是靠碰运气。

## 1. 记号

- `N`：棋盘边长，`4 ≤ N ≤ 9`
- 格子 `(r, c)`，`0 ≤ r, c < N`
- `region[r][c] ∈ [0, N)`：区域编号
- 解用排列表示：`p[r] = c` 表示第 r 行的猫在第 c 列
- **单元（unit）**：一行、一列、或一个区域
- 相邻：切比雪夫距离 ≤ 1（上下左右 + 对角线）

规则等价形式（两两猫之间）：

1. `p` 是 0..N-1 的排列（行/列各一）
2. `|p[r] - p[r-1]| ≥ 2`（相邻行不同列且不斜邻）
3. 每个区域恰好 1 个 `(r, p[r])`

## 2. 随机数与种子

| 项 | 决策 |
|---|---|
| RNG | **mulberry32**（32 位状态、整数运算为主、无浮点累积误差），跨平台一致 |
| 禁用 | `Math.random()` —— 不可复现，坏关无法定位 |
| 种子 | `FNV-1a 32(md-doku:{GENERATOR_VERSION}:{slot}:{attempt})` |
| 随机流 | 拆成三条独立流：`rngSolution`、`rngGrow`、`rngColor`（seed+1/+2/+3） |

**为什么拆流**：调区域生长参数时，答案排列不应改变。这样 A/B 调参时能直接对比"同一答案、不同分区"的效果，否则每次调参整个批次都变了，无法判断好坏。

`GENERATOR_VERSION` 从 1 开始，**任何会影响输出的改动必须 +1**，否则已发布的关卡与旧测试 fixture 的全部期望值失效。

## 3. Step A：生成答案排列

目标：产出满足「排列 + 相邻行列距 ≥ 2」的 `p`。

算法（随机化回溯）：

1. 逐行 `r = 0..N-1`
2. 候选列 = 未使用的列；若 `r > 0`，再过滤掉 `|c - p[r-1]| < 2` 的列
3. 用 `rngSolution` 洗牌候选顺序
4. 无候选 → 回溯上一行，换下一个候选
5. 全部行放置完成 → 得到一个解

要点：

- N=5 起必然有解（例如 `1,3,0,4,2` 型结构），搜索空间很小，回溯代价可忽略
- 允许"某个初始选择导致死路"，回溯吸收掉；如果整棵搜索树耗尽（实际不会发生），换 attempt 重来
- **不做**"解的对称性美化"（如 180° 旋转对称）——它会显著降低候选通过率，收益只有观感

成本：< 0.1ms。

## 4. Step B：区域生长（核心难点）

约束：N 个区域，每个区域**恰好包含一个解格**。

### 4.1 为什么这个方向，而不是反过来

"先画区域再求解"会得到大量无解或多解棋盘，只能反复重来；而"从解出发划区域"让 INV-2/INV-3/INV-4 变成**构造性质**，只剩 INV-1（唯一解）需要验证。把 6 条约束压缩成 1 条待验证，是这套管线能跑起来的根本原因。

### 4.2 数据结构

| 结构 | 内容 |
|---|---|
| `owner[r][c]` | 归属区域，`-1` 未分配；N 个解格预先归各自区域 |
| `size[i]` | 区域 i 的当前格数（初始均为 1） |
| `unowned` | 未分配格数（初始 `N² - N`） |
| `frontier(i)` | 区域 i 的候选扩展格集合（与区域 4 邻接的未分配格） |

N ≤ 9 时全盘 ≤ 81 格，每轮直接重算 frontier 也只需约 1000 次比较，**不需要增量维护**——先用最简单的实现保证正确。

### 4.3 生长循环

每轮：

1. **筛选可扩展区域**：frontier 非空，且 `size[i] < smax`
2. **按公平权重抽签**：`w_i = 1 / (1 + size[i])^1.2`
   —— 越小的区域越有优先权，防止"一个大区吃掉全盘、小区只剩 1 格"
3. **选扩展格**：在该区 frontier 中按权重抽签，`w = 1 + 2×同区邻居数 + 0.5×随机`
   —— 偏好与自身相邻更多格，形状更"敦实"，同时保留随机性
4. 写入 `owner`，`size++`，`unowned--`
5. `unowned == 0` 结束

终止性：每个区域有独立上限，且 `N × smax > N²`（见 4.4 数值），不会出现"所有区都满格但仍有空格"的僵局。若某区 frontier 提前枯竭（被其他区包围），它只是停止生长，最终会被尺寸下限检查拒绝。

### 4.4 尺寸阈值

| 参数 | 取值（N 为边长） | N=5 | N=7 | N=10 |
|---|---|---|---|---|
| `smin` | `max(2, floor(N/3))` | 2 | 2 | 3 |
| `smax` | `ceil(2.2 × N)` | 11 | 16 | 22 |
| 平均尺寸 | `N`（恒等） | 5 | 7 | 10 |

> 平均尺寸必然等于 N（N² 格 / N 区）。上下限只是排除极端，不改变总量。

### 4.5 结构检查（拒收项）

| 检查 | 阈值 | 目的 |
|---|---|---|
| 尺寸范围 | `smin ≤ size ≤ smax` | 排除"单格区"与"巨无霸区" |
| 尺寸均衡 | `max(size) / min(size) ≤ 3.5` | 防止难度强偏 |
| 整行/整列 | 区域不得覆盖某整行或整列 | 该区域会直接给出"必在此行"，过于送分 |
| 近满行 | 区域不得占某行 ≥ N-1 格 | 同上，弱化版 |
| 包围盒填充率 | `area / (bboxW × bboxH) ≥ 0.55` | 排除过度分散 |
| 周长比 | `perimeter / (4√area) ≤ 2.0` | 排除细长走廊形（视觉歧义） |
| 连通性 | BFS 可达全部区域格 | 构造上成立，仍做断言 |

> `perimeter` 指区域与外部（其他区或棋盘边界）相邻的边数。正方形该比值 ≈ 1.0，1×k 长条在 k≥10 时超过 1.7，k≥20 时超过 2.3。

### 4.6 配色

区域色不是装饰，是**规则的一部分**（同色 = 同区），必须可区分：

1. 建立区域邻接图（共享边即相邻）
2. DSATUR 贪心着色（按饱和度降序）
3. 调色板 ≥ 12 色，相邻区域色相角差 ≥ 30°
4. 无法满足时降级为"不同色即可"并记录告警

N ≤ 9、调色板 12 色 → 恒定可解（区域图的度数远小于色板容量）。

### 4.7 定向修补：把多解修成唯一（S1 实测后加入）

只靠"生成 + 拒收"在小尺寸上接受率过低：S1 实测 n=5 直接通过唯一性的候选约 **0.4%**，
n=7 更低，产 20 关需要数万次重试。在生长之后加入一步**定向修补**，同一批种子
20 关生成只需 43ms（`tools/lib/generate.js` 已实现）。

原理：多解时枚举出一个替代解 `alt`，把 `alt` 用到的某只猫所在的格子改划到相邻区域。
目标解 `p` 的格子一律不动，于是 `p` 仍然成立；`alt` 原来的区域空出、新区域被用两次，
`alt` 立刻失效。

```
for iter in 1..60:
  sols ← 枚举解，最多 3 个
  if |sols| == 1: 返回（并断言它就是 p）
  alt ← 第一个 ≠ p 的解
  打乱 alt 的 N 个格子
  for x = (r, alt[r]):
    if x 是 p 的解格: continue            # 目标解不可动
    A ← 区域(x); 若 size(A) ≤ 2: continue
    for B in x 的 4 邻接区域, B ≠ A:
      if size(B) + 1 > smax: continue
      if 去掉 x 后 A 不连通: continue
      region[x] ← B
      if 结构检查失败: 回滚; continue
      本轮已移动; break
  if 本轮没有发生移动: 返回失败
返回前再枚举一次，确认 |sols| == 1 且解 == p
```

实测接受率（Node 单核，每关最多 600 次候选，均含修补）：

| N | 接受率 | 平均修补轮数 | 说明 |
|---|---|---|---|
| 5 | ~35% | 5 | `balanced` 生长 |
| 6 | ~13% | 10 | `balanced` 生长 |
| 7 | ~2.5% | ~11 | `random` 生长（更碎但多解更易被修补掉） |

不变式：修补全程 `p` 始终合法；每次移动都做连通与结构检查；返回前重新枚举确认唯一。
修补只改变产能，不改变正确性。

> S3 若上到 N=8/9，接受率会继续下降，需要叠加：多起点重启、双格交换、
> 临时放宽结构阈值后再恢复。不要为此放松唯一解校验。

## 5. Step C：唯一解计数

### 5.1 状态

| 状态 | 表示 |
|---|---|
| 已用列 | `colMask`（N 位） |
| 已用区域 | `regMask`（N 位） |
| 上一行长猫的列 | `prevCol`（首行为 -1） |

逐行推进，第 r 行：候选列 = 未用 ∧ `|c - prevCol| ≥ 2` ∧ `region[r][c]` 未用。

### 5.2 剪枝（必须正确的三条）

| 剪枝 | 条件 | 正确性 |
|---|---|---|
| P1 数量 | 剩余行数 < 剩余未用区域数 | 每行最多消耗 1 个区域，倒推必然失败 |
| P2 区域可用性 | 某未用区域在剩余行中已无「列未用」的格子 | 该区域永远放不下 |
| P3 行可用性 | 某剩余行不存在「列未用 ∧ 该格区域尚未使用」的格子（**当前行**另加列距约束） | 该行放不下任何猫；未来行忽略列距属于放宽，安全 |

> P2 只检查"列未用"，不检查未来行的邻接约束——这是**放宽条件**，放宽只会漏剪不会错剪，是安全的。不要为了多剪而引入不安全的推断。

### 5.3 计数

- 到达第 N 行且 `regMask` 全满 → 解数 +1，记录当前解
- **解数到 2 立即返回**（不需要知道到底有几个解，只要知道"不是唯一"）
- 节点计数上限 **200,000**：超限判定为"病态候选"，直接丢弃

### 5.4 实际成本

| N | 典型耗时 | 说明 |
|---|---|---|
| 5–7 | < 1ms | 区域约束把搜索空间压得极小 |
| 8–9 | 1–3ms | 偶发回溯 |
| 10 | 3–10ms | 少数候选触发节点上限 |

200 个关卡 × 平均约 15 次候选重试 ≈ 数千次求解 → 秒级完成。

## 6. Step D：人类技巧求解器与难度评分

这是"难度不是感觉，是算出来的"的实现。

### 6.1 规则集（按顺序应用，直到不动点）

| 编号 | 技巧 | 推理 |
|---|---|---|
| R1 | 单元已满 | 某单元已有猫 → 该单元其余格全部排除 |
| R2 | 邻域排除 | 已放猫的 8 邻域全部排除 |
| R3 | 唯一候选 | 某单元无猫且只剩 1 个候选格 → 放猫 |
| R4a | 区域 → 行 | 某区域候选格全在同一行 → 该行其他区域的候选排除 |
| R4b | 行 → 区域 | 某行候选格全在同一区域 → 该区域在其他行的候选排除 |
| R4c/d | 列的同构 | 与 R4a/b 对偶 |
| R5 | 假设验证 | 选候选最少的单元试放一格，矛盾则回退 |

R4 是这类谜题的"分水岭"：**只有 R1–R3 能解的关，对熟练玩家会显得白给**。R4 带来的"锁定候选"感，正是 T3 以上难度的主要来源。

### 6.2 求值确定性

- 所有单元的遍历顺序固定（行 → 列 → 区域，编号升序）
- R5 分支选择固定：候选数最少的单元 → 编号最小 → 候选列升序
- **不使用随机**：同一盘面必然得到同一组指标

### 6.3 输出指标

| 指标 | 定义 | 用途 |
|---|---|---|
| `branchCount` | 成功路径上的 R5 分支次数 | 主难度因子 |
| `failedBranches` | 遇到的矛盾分支数 | 区分"顺推"与"试错" |
| `propagationRatio` | R1–R4 能推定的猫数 / N | 顺推比例 |
| `initialForced` | 空盘第一步是否有 R3/R4 可推 | 开局是否"有抓手" |
| `estimatedSeconds` | `25 + 8N + 45×branchCount` | 关卡列表展示、节奏控制 |

### 6.4 难度门禁（先尺寸约束，后逻辑打分）

> 早期版本按固定的 `branchCount`/`propagationRatio` 阈值做硬门禁；S3 实施后改为
> “逻辑分定档 + 尺寸上下限夹紧”，最终规则见 §14.1–14.3，此处只保留结论。

| 档 | 名称 | 允许 N | 逻辑分区间 |
|---|---|---|---|
| T1 | 入门 | 4–5 | score < 30 |
| T2 | 简单 | 5–6 | 30 ≤ score < 45 |
| T3 | 普通 | 6–7 | 45 ≤ score < 55 |
| T4 | 困难 | 7–8 | 55 ≤ score < 65 |
| T5 | 专家 | 8–9 | score ≥ 65 |

尺寸不是唯一判据：同一尺寸可由逻辑指标升入相邻档；尺寸只用于夹紧上下限，
保证 4×4 不会被评为专家、9×9 不会被评为入门。

## 7. Step E：先排难度骨架，再填内容

**不要"先生成再看落在哪一档"**——那样做出来的难度曲线是随机的，后期无论怎么调顺序都别扭。

正确顺序：

### 7.1 先定义 300 个槽位的目标档位

`tools/gen-pack.js` 用「200 关基线 + 100 关增量」的方式固定每个档位的尺寸与数量：

| 规则 | 实际实现 |
|---|---|
| 总量 | T1:30 / T2:75 / T3:105 / T4:60 / T5:30 |
| 基线 | `tools/lib/base-200.json`：S3 的 200 关，稳定 ID 全部保留 |
| 教学池 | 前 10 个播放位置改用 `tools/lib/easy-10.json`（4×4 / T1 / D0 / 零分支），ID 与顺序沿用原槽位，只换题面 |
| 增量 | T1 4×4×3 + 5×5×7；T2 5×5×12 + 6×6×13；T3 6×6×17 + 7×7×18；T4 7×7×13 + 8×8×3；T5 8×8×7 + 9×9×7 |
| 排序 | 前 10 关固定在原槽位；其余按 档位 → 尺寸 → 难度分 → 种子 全局排序，20 关/章，共 15 章 |
| 曲线 | 1–300 档位单调不降；第 1–10 关 4×4 零分支，第 11 关起 5×5；T5 位于第 14–15 章 |
| 降级 | 0 次；种子耗尽则构建失败并报告，不静默降级 |

### 7.2 按槽位填内容

对增量槽位：

1. 每个槽位最多 12 个确定性种子，每个种子给定候选预算（N=4 3000 → N=9 30000）
2. 每个候选：造解 → 生长 → 结构校验 → 唯一解 → 定向修补 → 评分 → 得档
3. 档位匹配目标 → 入座；不匹配 → 下一个种子
4. 12 个种子耗尽 → 回退到同档的另一尺寸（`FALLBACK_N`），并记录回退次数
5. 同档无可用回退 → 构建失败并报告，人工介入调参（禁止静默偏离）
6. 增量候选还要与基线 200 关一起做规范签名去重，命中旧布局直接拒收

因为槽位目标是先验的，**曲线 100% 符合设计**，不会出现"生成完发现第 7 章全是 T1"。
旧 200 关不重新生成，只参与合并、排序与去重；其 ID 随关卡内容移动但不变，
供 S4 存档按 ID 迁移。

前 10 关例外：`tools/gen-easy.js` 穷举全部 4×4 布局，只保留 4 个连通区域、
每区 2–7 格、不整行/整列占满、结构合格、唯一解、`analyzeDifficulty` 分数 0
且分支数 0 的题面；按边界形状差异贪心挑选 10 个互不重复者，偶数位做水平镜像，
让 4×4 的两种合法解型都出现。产物写入 `tools/lib/easy-10.json` 后，
`gen-pack.js` 把它按固定顺序装入原前 10 个槽位
（`L001 L202 L002 L003 L004 L005 L203 L006 L201 L206`），ID 和播放下标都不变。
`--check` 会独立复验这 10 关的零分支属性、唯一解与 ID/顺序。

### 7.3 每日挑战

同一套管线，单独一套 365 长度池：T3 312 道 + T4 53 道，全部预生成进包。
按本地日期取题：周日从 T4 池取"当年第几个周日"，其余从 T3 池取"当年第几个非周日"，
对池长度取模，跨年复用；同一日期全设备同题，不依赖联网或后端。

## 8. 非答案路径：运行时答案验证

与生成无关，但必须写死规则：

### 8.1 判定顺序

1. 猫数量 == N
2. 每行恰好 1 只
3. 每列恰好 1 只
4. 每个区域恰好 1 只
5. 任意两只猫切比雪夫距离 > 1

全部通过 = 通关。**判定过程不读取 `s`（答案串）**。

### 8.2 三层校验

| 时机 | 内容 | 成本 |
|---|---|---|
| 每次落子 | 局部冲突（行列区重复、八邻接） | O(N) |
| 每帧 | 不做 | — |
| 完成时 | 全量五条 | O(N²) ≤ 100 格 |
| 结算时 | 再次全量（防御撤销/存档异常） | O(N²) |

### 8.3 答案串的正当用途

- 提示系统（给正确的猫 / 给确定的空格）
- "检查"道具（判断当前盘面是否与唯一解冲突）
- 构建期校验

## 9. 编码、打包与加载

### 9.1 关卡编码

| 字段 | 类型 | 说明 | N=9 时 |
|---|---|---|---|
| `id` | string | 稳定 ID（`L001`…`L300`） | — |
| `n` | int | 边长（可由 `r` 长度推导，可省） | — |
| `r` | string | 区域串，`a–i` 每格一字符 | 81 |
| `s` | string | 答案串，每行猫列号一字符 | 9 |
| `t` | int | 难度档 1–5 | — |
| `v` | int | 生成器版本 | — |

平均 N≈7.3，约 115 字节/关 → 估算 300 关 ≈ 34KB（**实测 35KB**，见 §15），
每日 365 关 ≈ 45KB。合计 < 90KB，对包体毫无压力。

> 不用 JSON 对象存每格，不用位图压缩——字符编码已足够小，且肉眼可 debug（出问题时能直接看懂区域串）。

### 9.2 打包

- 300 关当前放在单个 `levels/pack-001.js`（35KB），直接同步 `require`
- `levels/index.js` 解码紧凑字段，补齐 `index`、`chapter`、稳定 ID 反查表
- 进一步扩产时再按包拆分；业务侧仍只认全局 1-based 序号，不受拆包影响

### 9.3 加载期自检（轻量）

解码单关时执行（< 1ms）：

1. `r.length == n²`，字符值 < n
2. 每个区域至少 1 格，且恰好含 1 个答案格
3. `s` 是合法排列且满足邻接约束
4. 每个区域连通（4 邻接）

**不重跑唯一性求解**——那是构建期职责，运行时不付这个成本；轻量自检能挡住"包损坏/编码错位"这类实际会发生的问题。

## 12. 调参手册（接受率低时按顺序动）

| 现象 | 先动什么 | 再动什么 |

## 14. S3 实施定稿（2026-11-19）

本节把前面的设计落到实际代码，并修订与最新需求不一致的地方；实现以本节为准。

### 14.1 尺寸与档位（覆盖 §6.4 旧表）

| 档位 | 名称 | 允许 N | 本档上限 |
|---|---|---|---|
| T1 | 入门 | 4、5 | 4×4 只能是 T1 |
| T2 | 简单 | 5、6 | 5×5 最高 T2 |
| T3 | 普通 | 6、7 | 6×6 最高 T3 |
| T4 | 困难 | 7、8 | 7×7 最高 T4 |
| T5 | 专家 | 8、9 | 8×8 可由逻辑升入 T5 |

N=9 的下限分数已经达到 T5，因此 9×9 恒为专家档；4×4 恒为入门档。
其余尺寸由逻辑指标在相邻两档间升降，避免“只看尺寸”。

### 14.2 人类技巧求解器（R1–R5）

候选格布尔网格 + 行/列/区已放猫状态：

- **R1 单元排除**：放猫后，同行、同列、同区其余格排除。
- **R2 邻域排除**：放猫后，切比雪夫距离 ≤1 的格排除。
- **R3 唯一候选**：无猫单元只剩 1 个候选 → 放猫。行、列、区都执行。
- **R4 锁定候选**：
  - 区候选全在同一行/列 → 该行/列其余区候选排除；
  - 行/列候选全在同一区 → 该区其余格排除。
  反复执行到不动点。
- **R5 分支**：R3/R4 停住时，选候选最少的单元（行→列→区，编号升序，候选按行列升序）
  试放；矛盾回退。单次评分最多 40000 个分支节点，超限的候选拒收。

指标全部确定性：`branchCount`（成功路径分支数）、`failedBranches`、
`propagationRatio`（空盘仅用 R1–R4 推定的猫数 / N）、`initialForced`、`nodes`。

### 14.3 难度分与门禁

```
sizeF   = (N - 4) / 5
branchF = min(branchCount / 3, 1)
failF   = min(failedBranches / 4, 1)
propF   = 1 - propagationRatio
score   = round(100 × (0.58×sizeF + 0.26×branchF + 0.10×failF + 0.06×propF))
```

分数档界：`T1 < 30 ≤ T2 < 45 ≤ T3 < 55 ≤ T4 < 65 ≤ T5`。
先由分数得档，再按尺寸夹到 `minTier(N)..maxTier(N)`：
N=4→1..1、5→1..2、6→2..3、7→3..4、8→4..5、9→5..5。
纯尺寸基准分（含空盘无顺推的 6 分）约为：
N=4→6、5→18、6→29、7→41、8→53、9→65，因此边界尺寸自然落档，
逻辑推理再把它升到相邻档（例如 5×5 经分支可升 T2，8×8 可升 T5）。

### 14.4 200 关骨架与生成

- 总量：T1 20 / T2 50 / T3 70 / T4 44 / T5 16 = 200。
- 每个档位按允许尺寸交替取 N，槽位目标先验固定；生成结果档位不符则换种子重试。
- 同一槽位多种子重试耗尽（最多 12 个种子 × 单种子候选预算）→ 构建失败并报告，不静默降级；
  仅在极端情况下回退到同档的另一尺寸，且记录次数。
- 最终按（档位，尺寸，难度分，seed）升序排入章节；20 关/章，共 10 章。
  同档内从小棋盘到大赛盘、再按逻辑分递增，首章从 4×4 教学起手。
- 结构阈值按 §4.5 全量执行；4×4 的“近满行”改用整行判定，避免教学尺寸被过度拒收。
- 唯一解求解器节点上限 200,000；超限候选拒收。

### 14.5 重复布局检测

区域编号本身无意义，因此把每关区域网格先按首次出现顺序重编号，
再取二面体群 8 种变换（4 旋转 × 镜像）中字典序最小者作为规范签名。
200 关内规范签名必须互不相同；同签名候选直接拒收。
唯一解保证“区域布局相同 ⇒ 玩法相同”，不需要再比较答案串。

### 14.6 数据格式与读取

正式关卡以 JSON 为源数据保存为 `levels/pack-001.json`：

```json
{"schema":3,"generator":"md-levelgen/2","total":300,"levels":[
  {"id":"L001","n":5,"r":"aaabb...","s":"13042","t":1,"d":11,"b":0,"seed":123}
]}
```

- `r`：n² 个字符，每格一个区域字母（a–i），比二维数组省 40% 空间。
- `s`：n 个数字字符，第 r 行猫所在列。
- `t`：难度档；`d`：难度分；`b`：成功路径分支数。
- 小游戏不能直接把 JSON 当模块 require，因此构建脚本同时生成
  `levels/pack-001.js`：`module.exports = <同一份 JSON>`。
  游戏只 require JS；Node 工具直接读 JSON。两份数据由同一构建过程产生，
  JSON 进版本库、不进小游戏包（`packOptions.ignore`）。
- `levels/index.js` 解码 `r`/`s` 为运行时 `regions`/`solution`，补 `id`、
  `index`、`chapter`，业务层无感知。
- 生成器与求解器放在 `js/domain/`，Node 工具与运行时共用；
  每日挑战已改用预生成日历池；运行时 `generateLevel(seed, n, {tier})` 仍可本地出题，
  无需后端，供未来无尽模式或兜底使用。

### 14.7 批量验收

- `node tools/gen-pack.js`：读取 200 关基线，生成 100 关增量，合并 300 关并全量复验，写 JSON/JS。
- `node tools/gen-pack.js --check`：只复验现有包，检查唯一解、结构、连通、去重、档位。
- `node tools/batch-test.js 1000`：1000 个生成任务的批量验证统计，
  输出成功、无解、多解（入池/候选拒收）、唯一解、平均耗时、难度分布、
  尺寸分布、结构拒收与求解超限数。

## 16. S5 每日挑战日历池（365 道）

- 生成器：`tools/gen-daily.js`，复用主线同一套造解/生长/定档/求解管线。

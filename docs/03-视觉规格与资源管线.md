# 视觉规格与资源管线 v1.0

> 目标：复刻参考产品的**观感**（同一视觉家族），不复刻其**文件**（插画、图标、版式）。
> 读者：负责美术的人 + 负责代码的人。本文同时是两者的接口契约。

---

## 1. 版权边界

| 类别 | 做 | 不做 | 说明 |
|---|---|---|---|
| 色彩体系 | 同家族奶油底 + 糖果色区域 | 逐格吸取其 hex 值 | 色彩本身保护弱，但整套配色 + 版式的组合是识别标志 |
| 形状语言 | 大圆角方块、浅描边、留白 | 像素级复刻间距/圆角/字重 | 圆角方块是通用语言，精确复刻构成风险 |
| 猫咪形象 | 自己的贴纸式猫头（参数化生成或委托绘制） | 描摹/搬运其黑猫表情 | 插画是最强的独创性表达 |
| 图标 | 自己的提示/撤销/擦除图标 | 复用其图标造型 | |
| 布局结构 | 顶部圆形按钮 + 居中数字、规则卡、色块棋盘、底部色带 | 逐元素复制其面板排版与装饰 | 功能布局本身不受保护，但**整体观感**要拉出差异 |
| 文案 | 自己的中文文案 | 复用其英文标题（New logic Puzzle 等） | |

**执行标准**：把两张截图并排放，应当能立刻看出"同类游戏"，但不能一眼看出"同一套 UI"。

原创增量（我们比参考多做的东西，也是差异化的证据）：

1. **区域图例条**：N 个猫头对应 N 个区域色，放猫后对应图例点亮 → 既是图例也是进度
2. **规则卡自适应折叠**：N ≥ 8 时折叠为一行图标，把高度还给棋盘
3. **X 的对比度自适应**：浅色区域用深棕 X，深色区域用白 X，而不是统一白色
4. **工具栏融入底部色带**：三个圆形按钮坐在色带上，功能与品牌区合并
5. **冲突色**：独立的错误红与抖动，参考产品没有这套反馈

## 2. 视觉解构：要复刻的 10 个特征

| # | 特征 | 实现要点 |

| 1 | 奶油底 + 白卡片 + 极浅描边 | 底色偏黄、卡片纯白、描边低对比 |

> S5.3 阶段 1 把 12 色统一向白色混入 12%：仍是多色相糖果色，但更接近竞品的粉彩色块。



> 色板顺序**不是**区域 id 到颜色的直接映射。`theme.region` 只是候选池，
> 每关实际取色由 `js/ui/region-colors.js` 计算，结果确定、不随帧变化。

**分配规则**：

1. 把该关区域图建成相邻图（上下左右 + 斜角相接都算相邻）。
2. 以 4 种区域排序 × N 个起点做多起点贪心，枚举所有“候选色 → 区域”的落色方案。
3. 每种方案按 CIELAB 色差（CIE76）打分：优先最大化相邻区域的最小 ΔE；
   全盘出现 ΔE < 28 的近色时按距离罚分，避免不相邻区域也混淆。
4. 取总分最高的方案作为该关配色。N ≤ 9，12 色候选足够保证同关不重复。

**实测**：300 关 × 4 套皮肤（奶油/薄荷/樱花/夜航）的最低相邻 ΔE 为 32.9
（薄荷皮肤 L199；奶油 40.8、樱花 34.6、夜航 33.7）；冒烟测试断言所有关卡、
所有皮肤相邻 ΔE ≥ 30，并打印当次最小值。

> 皮肤同样保持多色相，只调整整体冷暖与明度；不能做成单色渐变，
> 否则区域边界无法辨认。皮肤色值见 `theme.js` 的 `SKINS`。

**字体方案**：

| 用途 | 字体 | 说明 |
|---|---|---|
| 数字、短英文标题 | 圆体（站酷快乐体 子集） | 免费商用需在发布前核对官方最新授权条款 |

## 4. 布局规格

### 4.1 游戏界面纵向排布（375×812 基准）

```
safeTop (44)
├─ 顶部栏        56   返回圆钮 | Level/Score 两行 | 设置圆钮
├─ 图例条        40   N 个 24px 圆角方块
├─ 规则卡        72   三张等宽卡（N≥8 时折叠为 36）
├─ 呼吸间距      12
├─ 棋盘          343  = W - 32
├─ 呼吸间距      12
├─ 工具栏        64   撤销 / 擦除 / 提示（坐在底部色带上）
├─ 底部色带      96
└─ safeBottom (34)
```

### 4.2 关键尺寸公式（不许写死像素）

```
boardSize = min(W - 2×16, H_usable × 0.44)
tileSize  = (boardSize - 2×10 - (N-1)×gap) / N
```

| N | 格子尺寸（375 宽） | 评价 |
|---|---|---|
| 5 | ≈ 60px | 舒适 |
| 7 | ≈ 43px | 良好 |
| 9 | ≈ 33px | 偏小，需辅助反馈 |

**9×9 的点击风险与对策**：格子在 30–35px 时误触率明显上升。对策（三选一，S4 实测后定）：

1. 点击后 80ms 内允许"再点相邻格"修正
2. 长按后拖动选择（不落子）
3. 每次落子加图标放大 1.08 的即时反馈（不使用震动）

不允许的解法：放大棋盘到超出屏宽、或缩小间隙到看不清区域边界。

### 4.3 自适应规则

| 情况 | 处理 |
|---|---|
| 窄屏（≤ 360） | 边距 12，规则卡文案换行 |
| 高屏（≥ 812） | 底部色带增高，不加内容 |
| 矮屏（≤ 700） | 页头 46、HUD 26、图例 16、规则条 44（8/9 路 30），棋盘取 `min(宽, 可用高, H × 0.46)` |
| 安全区 | 顶部按钮下移，底部色带包住 home indicator |
| iPad | 棋盘按短边的 60% 封顶，四周留白，不拉伸 |

### 4.4 微信胶囊避让（硬约束）

右上角胶囊（`··· │ ⊙`）由微信系统绘制，永远盖在 Canvas 上方，游戏无法隐藏它。因此：

- `platform/env.js` 调用 `wx.getMenuButtonBoundingClientRect()` 读取胶囊矩形（px，
  屏幕左上角原点）；返回非法或 API 不可用时 `menu = null`，静默退回安全区，不白屏
- `ui/layout.js` 的 `topInset() = max(safeTop + 8, menu.bottom + 10)`；首页资源条、
  返回/帮助/签到/设置按钮、对局标题、规则卡、玩法说明弹窗、图鉴详情卡、结算内容
  全部从 `topInset()` 起排，**不得有任何可点/可读元素进入胶囊矩形**
- 矮屏（`h < 700`）同时压缩对局页头（52→46）与图例（30→26），把胶囊让位占用的
  高度还给棋盘，保证 320×568 上 9×9 格子仍 ≥ 24px
- 新增页面或弹窗必须走 `Layout` 具名锚点，不允许直接使用 `safeTop` 画顶部元素

## 6. 资源命名、图集与回退（"后期可改"的核心）

### 6.1 命名规范

```
类别/名称[/变体]
cats/black              # 默认黑猫
cats/cream/happy        # 奶油猫的开心表情
ui/icon-hint
board/frame
face/x-dark
chapter/wave-blue
```

- 全小写、连字符、无空格
- 变体只允许出现在最后一段
- **键名一经使用不得改名**（改名要同步 manifest 与数据表，工具会报错兜底）

### 6.2 图集

| 图集 | 内容 | 尺寸上限 |
|---|---|---|
| `atlas-ui` | 图标、按钮、卡片边框、色带 | 1024² |
| `atlas-cats` | 16 只猫 × 4 表情（normal/happy/surprised/sleepy） | 2048² |
| `atlas-board` | 棋盘外框、X、装饰 | 1024² |

- 导出 @2x PNG（透明），运行时按 DPR 取用上限 2
- 9-slice 用于卡片与色带（四边固定，中间拉伸）
- 单图集加载失败 → 用程序化绘制兜底，**不得白屏**

### 6.3 三级回退链

```
精确键（cats/cream/happy）
    ↓ 缺失
组默认（cats/cream）
    ↓ 缺失
程序化绘制（参数化猫头 / 纯色块 / 文字按钮）
```

意义：开发阶段完全不依赖最终美术，最终替换时无需改任何业务代码。

### 6.4 清单文件

`assets/manifest.js` 是唯一入口，每条记录：

| 字段 | 说明 |
|---|---|
| `key` | 资源键 |
| `atlas` | 所属图集 |
| `rect` | 在图集中的像素区域 |
| `slice` | 9-slice 的四边宽度（可空） |
| `anchor` | 锚点（默认左上） |

`tools/build-manifest.js` 负责：校验"数据表引用的键全部存在"、"manifest 里的键全部被引用（或列入白名单）"。

## 7. 主题与换肤

章节主题 = **一组令牌覆盖**，不是一套新图。

| 主题 | 覆盖项 |
|---|---|
| 猫咖（默认） | 原样 |
| 樱花街 | `bg.base` 偏粉、`accent.brand` 偏樱花粉 |
| 夜市 | 背景转深、文字转浅、区域色饱和度 +10% |
| 图书馆 | 木色边框、纸张纹理纹理层 |
| 雪国 | 冷白底、区域色降饱和 |
| 太空站 | 深底 + 区域色提亮 |

新增主题 = 在 `data/theme.js` 加一个覆盖对象 + 章节表里引用。**不改任何绘制代码。**

商店棋盘皮肤在 `theme.js` 的 `SKINS` 中提供整套 12 色候选板。皮肤只调整整体冷暖与
明度，必须保持多色相；单色渐变会让区域边界无法辨认，验收时同样跑冒烟测试的
“相邻区域 ΔE ≥ 30”断言。

## 8. 占位资产（S1 就能出画面）

S1–S3 阶段使用**程序化占位**，全部由 Canvas 绘制，不引入任何外部图片：

| 占位项 | 画法 |
|---|---|
| 猫头 | 马卡龙底色 + 圆形猫头 + 参数化耳形（尖/圆角/矮折）+ 6 种明亮眼神 + 8 种嘴型 + 6 种斑纹（纯色/浅梁/虎斑/口鼻/额斑/三花）+ 11 种配饰 + 腮红；支持 normal/happy/surprised/sleepy 表情 |

| 调颜色 | `data/theme.js` | 所有代码 |

- 绘制层不得出现 hex 字符串、字号、圆角数字

- 新增资源必须登记 manifest，构建脚本会阻断未登记引用

## 10.3 猫咪形象 v4（S5.3 阶段 2.1：马卡龙柔光，已实现）

`data/cats.js` 每只猫在 `base/patch/patch2/inner` 之外带六类外观参数：
`ear / eyes / mouth / pattern / accessory / acc`；
`draw.catFace(r, cx, cy, size, cat, opts)` 签名保持不变，内部按参数绘制。

整体为软萌日系轻手绘画风：正圆猫头（直径 `2R`），
头部略大；棋盘与图鉴延续头像构图（不画身体），保证 9×9 小格仍可读。
底色统一为低饱和马卡龙（奶油白、浅粉、薄荷绿、淡黄、
天空蓝、浅紫，另用橘/灰/炭等做品种点缀）。浅色猫用 `catLine` 暖棕细线
（`0.065R`），深色猫自动换浅色轮廓；**不使用面罩 / 单眼补丁 / 白色大眼罩**，
深色脸用浅色实心眼 + 深色瞳孔，浅色脸用深色实心眼。
16 只猫覆盖橘猫、奶牛猫、白猫、黑猫、三花猫、布偶猫、英短蓝、灰猫、
虎斑猫、暹罗猫的造型化参考，不追求写实骨骼与毛流。

| 参数 | 可选值 | 画法 |
|---|---|---|
| `ear` | `point` / `round` / `fold` | 尖三角耳 / 圆角三角耳 / 矮圆折片耳（不做高尖角） |
| `eyes` | `dot` / `sparkle` / `gentle` / `wide` / `happy` / `sleepy` | 亮面实心眼 / 双高光星眼 / 上眼睑柔和眼 / 放大实心眼 / 弯月笑眼 / 闭眼下弯 |
| `mouth` | `smile` / `w` / `open` / `tongue` / `line` / `pout` / `smirk` / `fang` | 小微笑 / W 嘴 / 小开口 / 微笑伸舌 / 一字嘴 / 抿嘴 / 斜笑 / 小开口 + 白虎牙 |
| `pattern` | `plain` / `blaze` / `tabby` / `muzzle` / `spot` / `calico` | 纯色 / 窄额心浅梁 + 小口鼻 / 额纹 + 颊纹 / 浅色口鼻 / 单侧额斑 / 三花双色斑块 + 奶油口鼻；均不遮眼 |
| `accessory` | `bell` / `scarf` / `glasses` / `flower` / `tear` / `bow` / `star` / `leaf` / `collar` / `headphones` / `crown` | 铃铛项圈 / 围巾 + 结与尾 / 细框眼镜 / 五瓣花 / 泪滴 / 蝴蝶结 / 四角星 / 双叶 / 项圈吊牌 / 耳机 / 小皇冠 |
| `acc` | `theme.js` 颜色令牌名 | 每只猫的配饰独立取色，不写死 hex |

- 16 只猫的六元组（耳/眼/嘴/斑纹/配饰/配饰色）两两不同，
  冒烟测试断言签名唯一，并逐一验证 11 种配饰、8 种嘴型、6 种斑纹都接入真实绘制；
  三花猫额外断言 `calico` 必须有不同于 `patch` 的 `patch2` 双色斑块。
- `opts.expression`：`normal`（默认）/ `happy`（弯月眼 + 开口笑）/ `surprised`（放大实心眼 + 小圆嘴）/ `sleepy`（闭眼 + 一字嘴），未知值回退 `normal`；结算页传 `happy`。
- 头身比 `R = size * 0.37`；主体为圆润大头，棋盘内仍按头像裁切。
  眉毛/眼睑/嘴线用小圆头线条；所有眼睛都有双高光，腮红在深色猫上提高不透明度。
- 光影为左上柔光 + 下半脸浅阴影：单只大图（`size > 64`）用一次径向/线性渐变，
  棋盘与图鉴小图用平涂，**禁止为每只棋盘猫创建渐变对象**；斑纹压在光影之上。
- 颜色只取 `theme.js` 的 `catInk/catLine/catNose/catBlush/catInner/coinFace/coinDeep/cta/brand/gold/success/text/textSoft` 等令牌；
  斑纹用底色与 `catInk` 混色，深色/浅色猫都可见；配饰颜色由每只猫的 `acc` 令牌决定。
- 28px 格（9×9 小屏）仍绘制耳朵、眼睛、鼻嘴与配饰；`size > 48` 才加胡须，避免小尺寸糊成一团；
  配饰尺寸控制在头部轮廓附近，不越出格子。
- 旧存档/旧数据缺少参数时回退 `point / dot / smile / plain / 无配饰`；
  旧值 `mask/patch` 不属于新斑纹集合，会安全落到 `plain`，不会报错。
- 墨墨固定为 `point / sparkle / smile / muzzle / bell / gold`：黑脸、浅口鼻、亮点眼与金铃铛，
  不再有单眼罩或白色眼圈；樱井为三花参考：`calico` + `patch2`，斑块避开眼睛。

> 视觉验收：`?scene=album&demo=all` 可解锁 16 只猫并排检查；
> 4×4/9×9 棋盘截图确认猫头不糊、不越格；首页、图鉴详情与结算页可看柔光与开心表情。
> 冒烟测试 365 项全绿（含正圆头形断言）。

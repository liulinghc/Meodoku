# 视觉规格与资源管线 v1.0

> 目标：复刻参考产品的**观感**（同一视觉家族），不复刻其**文件**（插画、图标、版式）。
> 读者：负责美术的人 + 负责代码的人。本文同时是两者的接口契约。

---

## 1. 版权边界

| 类别 | 做 | 不做 | 说明 |
|---|---|---|---|
| 色彩体系 | 同家族奶油底 + 糖果色区域 | 逐格吸取其 hex 值 | 色彩本身保护弱，但整套配色 + 版式的组合是识别标志 |
| 形状语言 | 大圆角方块、浅描边、留白 | 像素级复刻间距/圆角/字重 | 圆角方块是通用语言，精确复刻构成风险 |
| 猫咪形象 | 自己的贴纸式猫头（参数化生成或委托绘制） | 描摹/搬运其黑猫表情 | 插画是最强的独创性表达 |
| 图标 | 自己的提示/撤销/擦除图标 | 复用其图标造型 | |
| 布局结构 | 顶部圆形按钮 + 居中数字、规则卡、色块棋盘、底部色带 | 逐元素复制其面板排版与装饰 | 功能布局本身不受保护，但**整体观感**要拉出差异 |
| 文案 | 自己的中文文案 | 复用其英文标题（New logic Puzzle 等） | |

**执行标准**：把两张截图并排放，应当能立刻看出"同类游戏"，但不能一眼看出"同一套 UI"。

原创增量（我们比参考多做的东西，也是差异化的证据）：

1. **区域图例条**：N 个猫头对应 N 个区域色，放猫后对应图例点亮 → 既是图例也是进度
2. **规则卡自适应折叠**：N ≥ 8 时折叠为一行图标，把高度还给棋盘
3. **X 的对比度自适应**：浅色区域用深棕 X，深色区域用白 X，而不是统一白色
4. **工具栏融入底部色带**：三个圆形按钮坐在色带上，功能与品牌区合并
5. **冲突色**：独立的错误红与抖动，参考产品没有这套反馈

## 2. 视觉解构：要复刻的 10 个特征

| # | 特征 | 实现要点 |
|---|---|---|
| 1 | 奶油底 + 白卡片 + 极浅描边 | 底色偏黄、卡片纯白、描边低对比 |
| 2 | 棋盘像"拼图板" | 外框白底 + 圆角 + 柔和投影，棋盘内留白 |
| 3 | 区域 = 纯色块 | 无渐变无纹理，仅靠色相区分 |
| 4 | 白色粗 X | 粗笔画、圆角端点，压在色块上 |
| 5 | 猫头是"贴纸" | 深色描边、大眼、腮红、无身体 |
| 6 | 顶部圆形图标按钮 | 白底圆 + 细描边 + 深棕图标 |
| 7 | 猫头图例行 | 一排圆角小方块，每块一个区域色 + 猫头 |
| 8 | 三张规则卡 | 白底、细描边、卡内 3×3 小示意图 + 两行短文案 |
| 9 | 底部大面积色带 | 波浪形或大圆角，浅蓝，白色粗体标题 |
| 10 | 克制的动效 | 落下、弹一下、飘金币，≤ 240ms |

### 3.4 几何与字体（以 375×812 为设计基准，逻辑像素）

| 令牌 | 值 |
|---|---|
| 棋盘外框圆角 | 20 |
| 格子圆角 | 12（N ≤ 7）/ 8（N ≥ 8） |
| 卡片圆角 | 14 |
| 棋盘内边距 | 10 |
| 格子间隙 | 6（N ≤ 7）/ 4（N ≥ 8） |
| 卡片描边 | 2 |
| 顶部按钮直径 | 44 |
| 字号：HUD 数值 / 标签 | 30 / 13 |
| 字号：底部标题 | 26 |
| 字号：规则卡文案 | 12（**中文最小 12，不能再小**） |
| 字号：正文 / 辅助 | 15 / 12 |
| 动效：快 / 中 / 慢 | 120 / 240 / 400 ms，`ease-out` |

**字体方案**：

| 用途 | 字体 | 说明 |
|---|---|---|
| 数字、短英文标题 | 圆体（站酷快乐体 子集） | 免费商用需在发布前核对官方最新授权条款 |
| 中文标题 | 圆体子集 | 只保留 UI 用到的约 300–500 字 |
| 中文正文 | 系统字体（PingFang SC / 思源黑体） | 不打包，省包体 |

> 中文字体全量 3–10MB，绝不能整包进小游戏。构建期用 fonttools 子集化，产物目标 < 250KB；`wx.loadFont` 失败时静默回退系统字体，界面不得依赖字体加载完成。

**中文文案要压缩**：英文 "1 Cat per column and row" 在中文里要写成"每行每列各一猫"，规则卡最多 2 行、每行 ≤ 9 字。

## 4. 布局规格

### 4.1 游戏界面纵向排布（375×812 基准）

```
safeTop (44)
├─ 顶部栏        56   返回圆钮 | Level/Score 两行 | 设置圆钮
├─ 图例条        40   N 个 24px 圆角方块
├─ 规则卡        72   三张等宽卡（N≥8 时折叠为 36）
├─ 呼吸间距      12
├─ 棋盘          343  = W - 32
├─ 呼吸间距      12
├─ 工具栏        64   撤销 / 擦除 / 提示（坐在底部色带上）
├─ 底部色带      96
└─ safeBottom (34)
```

### 4.2 关键尺寸公式（不许写死像素）

```
boardSize = min(W - 2×16, H_usable × 0.44)
tileSize  = (boardSize - 2×10 - (N-1)×gap) / N
```

| N | 格子尺寸（375 宽） | 评价 |
|---|---|---|
| 5 | ≈ 60px | 舒适 |
| 7 | ≈ 43px | 良好 |
| 9 | ≈ 33px | 偏小，需辅助反馈 |

**9×9 的点击风险与对策**：格子在 30–35px 时误触率明显上升。对策（三选一，S4 实测后定）：

1. 点击后 80ms 内允许"再点相邻格"修正
2. 长按后拖动选择（不落子）
3. 每次落子加轻振动 + 图标放大 1.08 的即时反馈

不允许的解法：放大棋盘到超出屏宽、或缩小间隙到看不清区域边界。

### 4.3 自适应规则

| 情况 | 处理 |
|---|---|
| 窄屏（≤ 360） | 边距 12，规则卡文案换行 |
| 高屏（≥ 812） | 底部色带增高，不加内容 |
| 矮屏（≤ 667） | 规则卡默认折叠到 36，棋盘取 `H × 0.42` |
| 安全区 | 顶部按钮下移，底部色带包住 home indicator |
| iPad | 棋盘按短边的 60% 封顶，四周留白，不拉伸 |

## 5. 组件与状态

| 组件 | 状态 | 视觉 |
|---|---|---|
| 格子 | 空 | 区域色块，无内容 |
| | 标 X | 区域色 + 自适应色粗 X（笔画宽 = 格子宽 × 0.16） |
| | 猫 | 区域色 + 猫头贴纸，占格子 78% |
| | 选中 | 白色 3px 内描边 + 轻微浮起 |
| | 冲突 | 描边转 `state.conflict` + 横向抖动 240ms |
| | 高亮 | `state.highlight` 40% 叠加 + 外发光 4px |
| 猫头图例 | 未点亮 / 点亮 | 60% 不透明 → 100% + 猫头变大 8% |
| 规则卡 | 常态 / 演示中 | 白底浅边 → 橙色描边 + 卡内示意图动画 |
| 顶部按钮 | 常态 / 按下 | 白底 → 下移 1px + 阴影收窄 |
| 底部色带 | 游戏 / 首页 | 纯色带 + 标语；游戏页叠三个圆钮 |
| 结算面板 | 入场 | 卡片从 0.9 缩放 + 淡入，240ms |
| 飘字 | 金币/N 连击 | 上移 40px + 淡出，600ms，池化 |

## 6. 资源命名、图集与回退（"后期可改"的核心）

### 6.1 命名规范

```
类别/名称[/变体]
cats/black              # 默认黑猫
cats/cream/happy        # 奶油猫的开心表情
ui/icon-hint
board/frame
face/x-dark
chapter/wave-blue
```

- 全小写、连字符、无空格
- 变体只允许出现在最后一段
- **键名一经使用不得改名**（改名要同步 manifest 与数据表，工具会报错兜底）

### 6.2 图集

| 图集 | 内容 | 尺寸上限 |
|---|---|---|
| `atlas-ui` | 图标、按钮、卡片边框、色带 | 1024² |
| `atlas-cats` | 16 只猫 × 3 状态 | 2048² |
| `atlas-board` | 棋盘外框、X、装饰 | 1024² |

- 导出 @2x PNG（透明），运行时按 DPR 取用上限 2
- 9-slice 用于卡片与色带（四边固定，中间拉伸）
- 单图集加载失败 → 用程序化绘制兜底，**不得白屏**

### 6.3 三级回退链

```
精确键（cats/cream/happy）
    ↓ 缺失
组默认（cats/cream）
    ↓ 缺失
程序化绘制（参数化猫头 / 纯色块 / 文字按钮）
```

意义：开发阶段完全不依赖最终美术，最终替换时无需改任何业务代码。

### 6.4 清单文件

`assets/manifest.js` 是唯一入口，每条记录：

| 字段 | 说明 |
|---|---|
| `key` | 资源键 |
| `atlas` | 所属图集 |
| `rect` | 在图集中的像素区域 |
| `slice` | 9-slice 的四边宽度（可空） |
| `anchor` | 锚点（默认左上） |

`tools/build-manifest.js` 负责：校验"数据表引用的键全部存在"、"manifest 里的键全部被引用（或列入白名单）"。

## 7. 主题与换肤

章节主题 = **一组令牌覆盖**，不是一套新图。

| 主题 | 覆盖项 |
|---|---|
| 猫咖（默认） | 原样 |
| 樱花街 | `bg.base` 偏粉、`accent.brand` 偏樱花粉 |
| 夜市 | 背景转深、文字转浅、区域色饱和度 +10% |
| 图书馆 | 木色边框、纸张纹理纹理层 |
| 雪国 | 冷白底、区域色降饱和 |
| 太空站 | 深底 + 区域色提亮 |

新增主题 = 在 `data/theme.js` 加一个覆盖对象 + 章节表里引用。**不改任何绘制代码。**

## 8. 占位资产（S1 就能出画面）

S1–S3 阶段使用**程序化占位**，全部由 Canvas 绘制，不引入任何外部图片：

| 占位项 | 画法 |
|---|---|
| 猫头 | 圆形脸 + 两个三角耳 + 椭圆眼 + 三角鼻 + 腮红；参数化：底色、斑块、眼色、耳形、腮红 |
| X | 两条圆头粗线 |
| 图标 | 几何组合（箭头、垃圾桶、灯泡） |
| 卡片/色带 | 圆角矩形 + 纯色 |
| 字体 | 系统字体 |

好处：16 只猫在最终美术到位前就能"有形象"（参数不同即不同猫），而且这套参数表可以直接交给美术当线稿参考。

## 9. "后期修改"的改动映射

| 你想改什么 | 改哪里 | 不用改 |
|---|---|---|
| 调颜色 | `data/theme.js` | 所有代码 |
| 调节奏/尺寸 | `data/theme.js` + `ui/layout.js` | 业务与绘制逻辑 |
| 换某只猫的图 | 替换图集内对应帧 + manifest | 数据表、业务 |
| 加一只新猫 | `data/cats.js` + 图集帧（可先跑占位） | 业务逻辑 |
| 加一套主题 | `data/theme.js` | 绘制代码 |
| 加一个界面 | `ui/screens/` 新增 + 路由注册 | 其他界面 |
| 加一个道具 | `data/config.js` + 工具栏插槽 | 棋盘逻辑 |
| 改文案 | `data/copy.js` | 界面代码 |
| 换字体 | 构建脚本换字体文件 + 子集 | 界面代码 |

**硬约束（写进代码评审清单）**：

- 绘制层不得出现 hex 字符串、字号、圆角数字
- 界面层不得出现绝对坐标，全部用 `ui/layout.js` 的具名锚点
- 数据表不得出现图片路径，只能出现资源键
- 新增资源必须登记 manifest，构建脚本会阻断未登记引用

## 10. 性能约束

| 项 | 预算 |
|---|---|
| 图集总量 | < 1.5MB |
| 首屏需加载的图集 | 仅 `atlas-ui` |
| 单帧 drawImage | ≤ 60 次（棋盘静态层已预渲染为 1 次） |
| 字体子集 | < 250KB，加载超时 300ms 后回退系统字体 |
| 阴影/渐变 | 只允许出现在预渲染的静态层，不得每帧计算 |

## 11. 视觉验收清单（S7）

- [ ] 与参考截图并排：同类型可辨认，不构成"同一套 UI"
- [ ] 5×5 / 7×7 / 9×9 三档格子在真机上清晰可辨
